# v1.3.38.4 -- 7-day ranges on the existing indexes

Fifth release of the v1.3.38 series ("dashboard paints in under a
second"; scope in `docs/operations/ux-performance-review.md`). No
schema change and, by design, **no new index**. This is a bridge
until v1.3.40 (retention, ingest filter, hourly rollup) reshapes
`log_entries`. `argosVersion` `1.3.38.3` -> `1.3.38.4`.

## PHASE 0: do the covering indexes exist?

Yes for everything that is a count. On a `.backup` copy of prod
(480k `caddy_access` rows in the 7 d window; copy deleted after):

| Figure | As shipped (visits rows) | On existing indexes |
|---|---|---|
| requests per hour by status class | 5.7 s | `status BETWEEN a AND b` on `idx_log_entries_status_ts`, GROUP BY hour: **0.22 s per class** (the single `status >= 100 ... GROUP BY status/100` form makes the planner pick `idx_log_entries_timestamp` and visit rows: 7 s) |
| total / by source | 5.8 s / 0.16 s | `idx_log_entries_source_ts`, `idx_log_entries_timestamp`: 0.09-0.15 s |
| top hosts | 4.6 s (`host_domain`) | by `host_id` on `idx_log_entries_host_ts`: **0.13 s** (`BETWEEN` on that query also flips the planner to `idx_timestamp`, 7 s; pinned with `INDEXED BY`) |
| p50/p95/p99 durations | 6.4 s | no index carries `duration_ms`: newest 24 h only, **1.0 s** |
| top paths | 7.1 s | no index carries `path`: newest 24 h, **0.14 s** |
| bandwidth | 6.6 s | no index carries `size_bytes`: newest 24 h, **0.08 s** |
| logs/stats avg + p95 | 5.8 s + 7.9 s | newest 20,000 rows: 0.37 s + 0.05 s |

Useful fact: 0 non-access rows carry `status >= 100`, so a status
range implies `source = caddy_access` without touching the row.

## What ships

- `dashboard.Queries.Traffic`: ranges over 24 h without a host
  filter take `trafficLong`: four covering class queries for the
  hourly series, top hosts by `host_id` mapped through `hosts`,
  and `response_times` / `top_paths` / `bandwidth_out_bytes` over
  the newest 24 h (`detail_window: "24h0m0s"`, `detail_from`,
  `series_covers_range: true`). With a host filter the whole
  response is bounded to the newest 24 h and
  `series_covers_range` is `false` (no index carries host and
  status together; the busiest host is half the table).
- `db.ComputeStats` / `db.ComputeTimeseries`: filters that are
  only `from`/`to` (+ `source=caddy_access`) over more than 24 h,
  or unbounded, take the covering path: total, classes, sources
  and top hosts over the whole window; avg / p95 on the newest
  20,000 rows (`sample_n`); top paths on the newest 24 h
  (`detail_window`). Any other filter keeps the row queries.
- UI: each card that does not cover the full range says so in its
  own title; the Logs strip says "sampled, n=20,000". Cards that
  cover the range carry no note.
- Planner regression tests with `EXPLAIN QUERY PLAN` on the test
  DB (must show `COVERING INDEX <name>`, must not `SCAN`).
